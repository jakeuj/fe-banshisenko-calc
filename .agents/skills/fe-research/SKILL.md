# 遊戲機制與數值研究

這個專案的數值來自多個互相矛盾的攻略站。研究的目的是**用證據決定採用哪個值**，並把決定和理由寫回程式（`CORRECTIONS` 的 `why`、坐騎的 `note`、`verified: false`），讓之後的人知道為什麼。

## 證據強弱（由強到弱）

1. 遊戲內截圖或玩家實測（例：game8 凱伊×野生馬截圖、馬吉迪×戰車兵×汗血馬的實測數字）
2. 多個**獨立**來源一致（注意很多站互相抄，game8.jp 與 game8.co 不算完全獨立）
3. game8.jp 計算器 JSON（本專案的預設基準）
4. 單一來源

只有等級 1 或 2 的證據與 game8.jp 不同時才改預設值；否則維持 game8.jp，並告訴使用者可以在頁面「資料／校正」自行覆寫。

## 取得資料的方式

- **能拿到原始 JSON/CSV 就不要用摘要工具**。WebFetch 會把頁面交給小模型摘要，曾把中文名翻成英文、把數字搞錯；用 `curl` 或 `node -e "fetch(...)"` 直接抓原始檔再解析。
- game8 的數值直接讀 `tools/raw/game8.json`（欄位見 `fe-data-update/references/game8-columns.md`）。
- 各來源的網址、用途、存取方法：`references/sources.md`。
- 已知的來源衝突與目前的決定：`references/conflicts.md`。**開始查之前先看這份**，避免重做已經查過的事。
- 網頁數值是用 JavaScript 產生的（例如 game8 內嵌計算器）時，先找它載入的原始資料檔（game8 計算器就是 `assets.game8.jp/.../fe_banshisenko_ikusei_sim.json`）；找不到再用內建瀏覽器的 `get_page_text` / `javascript_tool` 讀已渲染的頁面。
- 請子代理查資料時，要求它回傳**原始數字與網址**，不要只給摘要；數值交叉比對後再採用。
- 比對 game8.jp（線上 vs 快取）與 game8.co 成長率頁（vs 目前 `data.js`）直接跑 `node tools/check-sources.mjs`，它解析原始 JSON/HTML，不經摘要工具。英文來源的名稱對照在 `tools/names-zh.mjs` 的 `EN_UNIT` / `EN_CLASS`。
- 比對騰訊文件社群表（角色成長、職業成長與補正、坐騎、戰車）跑 `node .agents/skills/fe-research/scripts/qq-sheet.mjs compare`；看單一分頁用 `dump <分頁id> <輸出檔>`（輸出放 scratchpad，不要提交）。它會先抓頁面拿 cookie 再呼叫 API（沒 cookie 會 401），並解好 protobuf 的字串池、數字池（負數與 ≥129 的數）。簡中名稱對照在 `names-zh.mjs` 的 `CN_UNIT` / `CN_CLASS` / `CN_MOUNT`，簡中 wiki 也用同一套名稱。
- 用 canvas 繪製的線上試算表（騰訊文件等）`get_page_text` 讀不到儲存格：先找它背後的資料 API（騰訊是 `dop-api/opendoc`），不要嘗試截圖辨識。

## 使用者回報遊戲內數值時

遊戲的角色成長率畫面顯示的是**合計**（game8 凱伊×野生馬截圖證實）：

`顯示成長 = 個人 + 職業 + 坐騎成長 × 倍率（一般 1、戰車兵 2）+ 戰車加成（僅戰車兵）`

1. 問清楚：角色、當下職業、有沒有配坐騎（哪一隻）、戰車兵的戰車狀態、哪一項、畫面上的數字。
2. 換算：
   - 要驗證**角色**個人值：`個人 = 顯示 − 職業 − 坐騎 × 倍率 − 戰車`，職業那一項要用各來源一致的值（不在 `conflicts.md` 的職業表裡）。
   - 要驗證**職業**值：`職業 = 顯示 − 個人 − …`，角色那一項要各來源一致（不在 `conflicts.md` 的角色表裡）。
   - 角色和職業那一項**都有爭議**時解不出來，請使用者換一個職業（或換一個角色）再看。
   - 穆的「成長之兆」+20 已含在 game8 的個人值裡；遊戲畫面是否也含 +20 未確認，用穆驗證時要說明這點。
3. 例：哪吒當劍客（劍客力 +0，各來源一致）時力量顯示 45 → 個人力 = 45，推翻 game8 的 55（已寫入 `CORRECTIONS` 的 `why` 與 `conflicts.md`）。
4. 結果交給 `fe-data-update`：與現有資料一致時只補證據（`why`、`conflicts.md`）；不一致時加 `CORRECTIONS`。實測是最強證據，就算 game8.jp 與 game8.co 一致也照實測改。

`conflicts.md` 的「可請使用者在遊戲內確認」列出目前靠實測就能定案的項目與該看哪個職業；使用者手上剛好有那個角色或職業時，可以主動請他看一下。

## 使用者提供的截圖／表格

先判斷是不是已經整合過的來源，逐項比對，不要當成新證據重複加入：

- **騰訊文件坐騎表**（`sources.md` 的 `bxlbpf` 分頁）：簡中、深色底、浮水印「江雪之舞和小团体自制 禁止转载」，欄位有「属性加成（满级）」、各能力成長、「投喂诱捕素材」「喜好蔬菜」「地点」，最下面有「战车（初始）」「战车（多轮升级）」兩列。數值已整合進 `mounts.mjs`，用 `qq-sheet.mjs compare` 比對即可。表本身的已知錯誤：莫諾凱洛斯數字欄漏了 HP（文字寫「1HP」、合計寫 20）；布克發拉斯的 +10 填在防守欄（文字與放生飾品都是魔防）；戰車（初始）各項合計 45 卻寫總和 50。
- 這張表的「喜好蔬菜」欄（例：野生馬 尤那魅・椰棗・亞曼菊；餵食提升友好度用）**沒有收錄**：來源標明禁止轉載、只填了 5 隻、與成長計算無關。使用者明確要求才加。
- **繁中社群坐騎表**（繁體，「類別屬性加成(滿級)」「誘捕素材」「特殊技能」）：專案最早的坐騎名稱來源（飲魯尼魯斯、飛馬）。其中「聖飛馬 3速2魔防」是野生飛馬的值誤植；「野生馬 2技1速1防」「野生飛馬 2速1魔防」只有 3–4 點，不是滿級值。
- 其他圖片：數值與 `mounts.mjs` / `data.js` 不同時，先對照 `conflicts.md`，再依本技能的證據強弱決定。

## 尚未解決的問題（由重要到次要）

找到證據時更新 `references/conflicts.md`，並依 `fe-data-update` / `fe-growth-engine` 修改程式。

1. 坐騎友好 Lv1–4 每一級加在哪一項（尤其馬系的成長分配）。有了才能做「友好度等級」選項。
2. 戰車兵之道：戰車加成的數值已知（`mounts.mjs` 的 `CHARIOT_STAGES`，初始 / 多輪升級後），但**何時升級**（幾級、幾輪）未知；「初始戰車」各項合計 45 與表上寫的 50 不符，缺一項未確認。戰象兵之道完全沒有資料。
3. 戰車兵的坐騎**能力**加成是否也 ×2。
4. 紅聖飛馬的能力與成長加成（羅西南已由騰訊文件表確認）。
5. 坐騎種類：redfreshet 說有 28 種，目前只收錄 19 種；象系沒有可捕獲的資料。
6. 能力上限（game8 的上限欄位全空）。
7. `references/conflicts.md` 中各職業的速度／技巧對調與角色個人值差異：需要遊戲內數值才能定案，方法見「使用者回報遊戲內數值時」，待確認清單在 `conflicts.md` 的「可請使用者在遊戲內確認」。
8. 最上級、神將職與 7 名角色（貝特蘭、內森、齊利科、安娜、亞絲望、塔霍尼雅、庫拉普卡）的繁中正式名稱。

## 研究坐騎時要記得

- 能力/成長加成隨友好 Lv1–5 提升，目前只有 Lv5 數值可靠。
- 馬系的成長加成不是能力 ×5（含 HP，分配不同）；鴕鳥/天馬/巴烏系是 ×5。
- 戰車兵：坐騎**成長**加成 ×2 已驗證；**能力**加成是否 ×2 未知。
- 只有凱伊篇（第 1 部 5 章起）與救世篇能捕獲；其他路線只有伊歐的羅西南、亞歷山卓的布克發拉斯。

## 比對腳本的結果怎麼讀

`check-sources.mjs` 與 `qq-sheet.mjs compare` 只列出**與目前 `data.js` 不同**的項目。逐筆對照 `references/conflicts.md`：

- 已記錄 → 已知衝突，不要重改；可以在該列補上「又一個來源」。
- 沒記錄 → 依本技能的證據強弱判斷；結論（不論改或不改）都寫進 `conflicts.md`。
- 比對完在 `conflicts.md` 更新「最近一次比對」那一行（日期、來源、結果）。

## 產出

回報時列出：結論、採用的值、證據（附網址或截圖描述）、與現有資料的差異。若要改資料，交給 `fe-data-update` 的流程處理（改 `names-zh.mjs` / `mounts.mjs` / `CORRECTIONS`，再重新產生與測試），並在 `references/conflicts.md` 補一行紀錄。
